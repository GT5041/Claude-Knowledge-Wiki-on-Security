<a id="t1"></a>
### `T1` — ガバナンス・認証・コンプライアンス

**一言でいうと：** Anthropic はセキュリティプログラム・認証・コンプライアンス成果物を Trust Center で公開している。適用される契約はプラン次第。

- Trust Center（<https://trust.anthropic.com>）がコンプライアンス成果物の正式な所在です。Claude Code の公式セキュリティドキュメント自身が、SOC 2 Type 2 報告書や ISO 27001 証明書などの取得先としてここを案内しています。`[S1]`
- Anthropic は Transparency Hub も公開しており、製品の法務／コンプライアンスドキュメントから参照されています。`[S3]` `[S10]`
- **適用される規約：** Team／Enterprise／Claude API は Commercial Terms of Service、Free／Pro／Max は Consumer Terms。既存の商用契約がある場合、直接契約（1P）でも Amazon Bedrock／Google Cloud's Agent Platform 経由（3P）でも、別途合意がない限り Claude Code の利用にも及びます。`[S3]`
- **医療（BAA）：** Anthropic と締結した BAA は、**当該組織で ZDR が有効な場合に限り**、Claude Code 経由の API トラフィックにも及びます。`[S3]` API 自体については HIPAA readiness が別建ての枠組みです（[`T3`](#t3) 参照）。`[S5]`
- **許容される利用**は Anthropic Usage Policy に従います。`[S3]` `[S9]`
- **認証方式は設計に影響します：** OAuth サインインはサブスクリプション購入者向け、プロダクトを開発する場合は Claude Console または対応クラウドプロバイダ経由の API キーを使います。サードパーティ開発者が自社アプリに Claude.ai ログインを提供すること、Claude.ai の資格情報やセッショントークンを収集・保存・仲介することは認められていません。`[S3]`

> **トレーサビリティに関する注記：** 本ページ作成環境では `trust.anthropic.com`／`anthropic.com`／`privacy.claude.com`／`support.claude.com` に直接到達できませんでした（エグレス制限）。これらに関する記述は、それらを引用している Anthropic 製品ドキュメント `[S1]` `[S3]` `[S5]` に基づく二次的な記載です。**リンク先そのものを正とし、認証範囲や日付を評価資料に引用する前に必ず一次情報で確認してください。**

<a id="t2"></a>
### `T2` — データの取り扱い・保持・モデル学習

**一言でいうと：** 商用契約下のトラフィックは既定ではモデル学習に使われない。保持期間はプランとプライバシー設定で決まる。

**学習ポリシー** `[S2]`
- *コンシューマ（Free／Pro／Max）：* ユーザー自身の設定が**オンの場合にのみ**、将来のモデル改善に利用されます（これらのアカウントからの Claude Code 利用を含む）。設定はいつでも変更可能です。
- *商用（Team／Enterprise／API／サードパーティプラットフォーム／Claude Gov）：* Anthropic は商用規約下で Claude Code に送信されたコードやプロンプトを生成モデルの学習に**使用しません**。ただし顧客が明示的にオプトインした場合を除きます（例：Development Partner Program。組織管理者が明示的に有効化する必要があり、ファーストパーティ API 限定）。
- API 側の約束： 保持されたデータは、明示的な許可なくモデル学習に使われることはありません。`[S5]`

**保持期間** `[S2]`

| 対象 | 保持期間 |
|---|---|
| コンシューマ（データ利用設定 **オン**） | 5 年 |
| コンシューマ（データ利用設定 **オフ**） | 30 日 |
| 商用（Team／Enterprise／API）標準 | 30 日 |
| 商用（ZDR 適用） | [`T3`](#t3) を参照 |
| `/feedback`・`/bug`・`/share` で送信したトランスクリプト | 5 年 |
| セッション品質サーベイの追加ステップで共有したトランスクリプト | 最大 6 か月 |
| ローカルの Claude Code トランスクリプト（`~/.claude/projects/` に平文） | 既定 30 日（`cleanupPeriodDays` で調整可） |

組織側のデータストアは別の保持体系を持ちます。Activity Feed は 6 年、Claude アプリのローカルセッショントランスクリプトは既定 6 年（組織のカスタム保持期間を設定している場合はその期間）、リモート Cowork セッショントランスクリプトは削除しない限り 6 年です。`[S5]`

**通信・保存時の暗号化** `[S2]`
- プロンプトと出力は TLS 1.2 以上で送信されます。Claude Code は一般的な VPN や LLM プロキシと互換性があります。
- 保存時暗号化はモデルプロバイダに依存します。Anthropic API はインフラレベルのディスク暗号化（AES-256）、Amazon Bedrock は AWS 管理キーによる AES-256（KMS による顧客管理キーも可）、Google Cloud's Agent Platform は Google 管理キー（CMEK 可）、Microsoft Foundry はホスティング方式次第（"Hosted on Azure" ではプロンプトと出力は Azure 内に留まり、利用メタデータと安全性システムがフラグした内容のみ Anthropic へ送られます）。

**テレメトリ** `[S2]`
- *メトリクス*（レイテンシ・信頼性・利用パターン）：コード、プロンプト、ファイルパスは**含まれません**。`DISABLE_TELEMETRY=1` でオプトアウト。
- *エラーレポート*：Claude Code 内部のスタックトレース。既知のシークレット・パス・メールアドレスのパターンはマシンから出る前に秘匿化されます。`DISABLE_ERROR_REPORTING=1` でオプトアウト。
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` で非必須通信を一括無効化できます。ただし **2 つは対象外**：WebFetch のドメイン安全性チェック（個別に `skipWebFetchPreflight`）と公式マーケットプレイスの自動インストール（`CLAUDE_CODE_DISABLE_OFFICIAL_MARKETPLACE_AUTOINSTALL`）。
- Bedrock／Google Cloud's Agent Platform／Microsoft Foundry／Claude Platform on AWS では、エラーレポート・テレメトリ・バグ報告は既定で**オフ**です。

**出典：** `[S2]` `[S5]`

<a id="t3"></a>
### `T3` — ゼロデータ保持（ZDR）と規制対象ワークロード

**一言でいうと：** ZDR は「応答返却後にプロンプトと応答を保存しない」こと。ただし適用範囲は限定的で、セルフサービスでは有効化できず、対象外の機能が複数ある。

**API における ZDR** `[S5]`
- 対象：Messages API・Token Counting API の適格機能、商用組織の API キーで使う Claude Code、または ZDR 有効な Claude Enterprise 経由の Claude Code、および申請ベースの Claude Platform on AWS。
- **対象外：** Claude Console（Playground 含む）、Claude Managed Agents、コンシューマプラン、Claude Team／Enterprise の製品 UI（Enterprise 上の Claude Code は例外）、Claude for Excel、Covered Models、サードパーティ連携。ZDR 組織では CORS が非対応のため、ブラウザからの呼び出しはバックエンドプロキシ経由にしてください。
- ZDR 適格性が "No" の機能はブロックされるわけではなく、**設計上ステートフル**です（Batch API はジョブを、Files API はファイルを保存し、コード実行は永続コンテナを使用）。使うこと自体が、そのデータについて ZDR の枠外に出るという意思決定になります。

**Claude for Enterprise 上の Claude Code における ZDR** `[S4]`
- 適格アカウントのみ。標準 Enterprise プランには含まれず、管理画面からは有効化できず、Anthropic による**組織単位**の有効化が必要です。**同一アカウント配下の新規組織には自動的に継承されません。**
- ZDR 有効組織でも、ユーザー単位のコスト管理、Analytics ダッシュボード、サーバー管理設定、監査ログは利用できます。
- **ZDR 下で無効化される機能**（バックエンドで強制）： Claude Code on the Web、デスクトップアプリのクラウドセッション、Claude Tag、Artifacts、フィードバック送信（`/feedback`・`/bug`・`/share`）、Remote Control。
- **ZDR 有効時でも対象外：** claude.ai のチャット、Cowork、Claude Code の Analytics メタデータ、ユーザー／シート管理データ、サードパーティ連携。
- **ルーティングが重要：** ZDR は当該 ZDR 組織に認証されたリクエストに適用されます。開発者が個人アカウントでサインインした場合は対象外です。`forceLoginMethod` / `forceLoginOrgUUID` のマネージド設定でログイン先を固定してください。`[S4]` `[S8]`

**HIPAA readiness** `[S5]`
- ZDR とは別の枠組みであり、PHI を扱うなら**こちらが正解**です（即時削除ではなく、PHI のライフサイクル全体にわたる暗号化・アクセス制御・監査ログを適用）。両方は不要です。
- **組織単位**で強制され、非適格機能は `400 invalid_request_error` でブロックされます。HIPAA 対象外のワークロードには別組織を使ってください。
- 適格組織は Claude Console → Settings → Privacy から標準 BAA を締結して有効化できます。個別交渉の BAA は営業経由です。

**Covered Models** `[S5]` `[S4]`
- Claude Fable 5.1、Mythos 5.1、Fable 5、Mythos 5 は Covered Models に指定され、**30 日のデータ保持が必須**です。明示的な許可がない限り ZDR では利用できません。ZDR 組織は特定ワークスペースのみ 30 日保持を有効化して利用し、他ワークスペースはゼロ保持を維持できます。

**枠組みに関わらず保持される場合** `[S5]` `[S4]`
- 法令上必要な場合、および自動化された Trust & Safety システムが内容をフラグした場合、Anthropic は入力と出力を**最大 2 年間**保持することがあります。

**出典：** `[S4]` `[S5]`

<a id="t4"></a>
### `T4` — モデルレベルの安全性とセーフガード

**一言でいうと：** モデルは複数ある統制のひとつ。操作への耐性は「強力な既定値」であって「境界」ではない。

- Claude モデルはプロンプトインジェクションに*耐性を持つよう設計*されています。Anthropic はデプロイ担当者に対し、モデル概要と**実際にデプロイするモデルのシステムカード**で評価結果を確認するよう案内しています。そのうえで多層防御が明示的に推奨されています。`[S7]`
- ジェイルブレイクやインジェクションに対して Claude は「本質的に強靭（inherently resilient）」と説明されており、ドキュメント化された対策は**ガードレールを強化するもの**であって、モデルの挙動を代替するものではないと位置づけられています。`[S12]`
- computer use ツールでは、スクリーンショット内のプロンプトインジェクションの可能性を検知し、実行前にユーザー確認を求めるよう Claude を誘導する**追加の分類器**が稼働します（オプトアウト方法もドキュメント化）。`[S12]`
- Claude Code の **auto モード**では、人間の代わりに別の分類器モデルがアクションをレビューし、危険と判断したものをブロックします。明示的な ask／deny ルールは引き続き有効で、組織は auto モード自体を無効化できます。`[S1]`
- フロンティアリスクのガバナンス（Responsible Scaling Policy と AI Safety Level 標準）、モデルのシステムカード、透明性レポートは Anthropic 自社サイトにあります。`[S9]` `[S10]` **具体的な内容を引用する前に、必ず一次情報で最新版を確認してください。** レベル指定やポリシーのバージョンはモデルリリースごとに変わり得るうえ、本ページ作成環境からは検証できませんでした。

<a id="t5"></a>
### `T5` — プロンプトインジェクションと非信頼コンテンツ

**一言でいうと：** 同じ名前で呼ばれる 2 つの異なる脅威モデルがあり、対策も異なる。

| | 直接インジェクション／ジェイルブレイク | 間接インジェクション |
|---|---|---|
| 攻撃者 | アプリケーションの**利用者本人** | Claude が読むコンテンツに影響を与えられる**第三者** |
| 経路 | 細工したプロンプト | Web ページ、メール、文書、OCR テキスト、ツール結果、リポジトリの README |
| 狙い | ガードレールの回避 | **利用者本人の権限を使って**エージェントを乗っ取る |

`[S12]`

**Claude Code 側の保護機構** `[S1]`
- パーミッションシステム。Manual モードでは重要な操作に明示的承認が必要。
- リクエスト全体を踏まえた文脈解析、コマンドインジェクションに対する入力サニタイズ。
- `curl`・`wget` などネットワーク取得系コマンドは**既定で自動承認されません**。
- Web fetch は**独立したコンテキストウィンドウ**を使い、取得内容が本体コンテキストに直接注入されないようにしています。
- Web 検索の結果は生のまま渡さず**要約**されます。`[S7]`
- 初回のコードベースと新規 MCP サーバーには信頼確認（trust verification）。**注意：`-p` による非対話実行では無効化されます。**
- コマンドインジェクション検知：疑わしい bash コマンドは、以前に許可リストへ入れていても手動承認が必要。マッチしないコマンドは**フェイルクローズ**。
- 複雑な bash コマンドには自然言語の説明が付き、人間がレビューできるようになっています。
- 資格情報の安全な保存：利用可能な場合は macOS Keychain、Windows／Linux ではファイルパーミッションで保護。
- ⚠️ Windows：WebDAV の有効化や `\\*` パスへのアクセス許可は非推奨です。WebDAV は Microsoft により非推奨化されており、パーミッションシステムを迂回したネットワークリクエストを誘発し得ます。

**Claude 上で開発する場合のアプリ側対策** `[S12]`
1. 非信頼コンテンツは**必ず `tool_result` ブロックに入れる**。システムプロンプトや素の user テキストには入れない。Claude はツール結果内の指示を懐疑的に扱うよう訓練されています。
2. ツールの description か結果の構造で、**内容の性質と出所**を明示する。
3. システムプロンプトに非信頼コンテンツの扱い方針を明示的に書く。
4. 第三者由来の文字列は **JSON エンコード**し、引用符の閉じによる「脱出」を防ぐ。
5. **自分の指示をツール結果に入れない**。指示は後続の user ターンで送る。
6. 最小権限：不要なシークレットを与えない、ツールはサンドボックスで実行、権限は最小スコープに。
7. ツール出力を `tool_result` として返す前に、軽量モデル（Claude Haiku 4.5 ＋ structured outputs）で**スクリーニング**する。
8. ユーザー入力も事前スクリーニング（有害性判定、入力バリデーション）し、繰り返す違反者はスロットリングまたは遮断する。
9. デプロイ前に、意図的にインジェクションを仕込んだ文書で**自前のエージェントをレッドチーミング**し、出力を継続監視する。

**利用者として非信頼コンテンツを扱うとき** `[S1]`
承認前にコマンドを確認する／非信頼コンテンツを直接 Claude にパイプしない／重要ファイルへの変更を検証する／スクリプト実行や外部サービス呼び出しは VM 内で行う／不審な挙動は `/feedback` で報告する。

> Anthropic は「これらの保護はリスクを大幅に低減するが、**いかなるシステムもすべての攻撃に完全に免疫ではない**」と明言しています。`[S1]`

**出典：** `[S1]` `[S7]` `[S12]`

<a id="t6"></a>
### `T6` — エージェントの権限と承認モデル

**一言でいうと：** パーミッションは「**実行されるか**」を、分離は「実行された後に**どこまで届くか**」を決める。両方必要。

- **Manual モード**は読み取り専用で開始します。編集・テスト実行・コマンドは都度確認され、1 回限りか恒久かを選べます。読み取り専用コマンド群（`ls`、`cat`、`git status` など）は確認なしで実行されます。`[S1]`
- **作業ディレクトリ境界：** Manual モードでは起動フォルダとそのサブフォルダにのみ書き込み、それ以外の読み取り（Read／Grep／Glob）も確認されます。追加ディレクトリで拡張、サンドボックスの `denyRead` ルールで読み取り専用 Bash の読み取り範囲を絞れます。`[S1]`
- **Accept Edits モード**は、作業ディレクトリ内のファイル編集と一部のファイルシステム系 Bash コマンド（`mkdir`、`touch`、`rm`、`mv`、`cp`、`sed`）を自動承認します。それ以外は引き続き確認されます。`[S1]`
- **auto モード**は人間の確認を分類器に置き換えます。これは**アクション単位の統制であって分離境界ではありません**。`[S1]` `[S6]`
- **`--dangerously-skip-permissions`** は確認を完全に無くします。Anthropic のガイダンスは「必ずコンテナ・VM・sandbox runtime の内側で、かつ非 root ユーザーとして実行する」こと（Linux／macOS では root だとこのフラグでの起動自体が拒否されます）。`[S6]`
- **bash ルールの評価方法：** コマンドは AST に解析されてルールと照合されます。解析できない、またはマッチしないコマンドは承認が必要で、`eval` のような構文は allow ルールがあっても常に承認が必要です。これは**パーミッションゲートであってサンドボックスではありません**。組み込みチェック（`rm`／`rmdir` のクリティカルパスチェック、保護パスリスト）を除き、対象や影響から危険性を推論するものではありません。`[S7]`
- **組織的な強制：** マネージド設定、バージョン管理された共通パーミッション設定、`/permissions` による定期監査、セッション中の設定変更を監査／ブロックする `ConfigChange` フック。`[S1]` `[S8]`
- **責任の所在は明示されています：** 「Claude Code はあなたが付与した権限しか持たない。承認前に提案されたコードとコマンドの安全性を確認する責任はあなたにある」`[S1]`

**出典：** `[S1]` `[S6]` `[S7]` `[S8]`

<a id="t7"></a>
### `T7` — 分離とサンドボックス

**一言でいうと：** 脅威モデルに合う境界を選び、その境界の「外に残るもの」を把握する。

| 方式 | 境界の内側に入るもの | Docker 要否 | 導入コスト | 分離強度 |
|---|---|---|---|---|
| サンドボックス化 Bash ツール（`/sandbox`） | Bash コマンドとその子プロセスのみ | 不要 | 最小（macOS）／低（Linux・WSL2） | コマンド単位 |
| sandbox runtime（`@anthropic-ai/sandbox-runtime`） | Claude Code プロセス全体：ファイルツール、MCP サーバー、フック | 不要 | 低 | 良好（安全な既定値） |
| Dev container | 開発環境全体 | 必要 | 中 | 構成次第 |
| カスタムコンテナ | 開発環境全体 | 必要 | 中〜高 | 構成次第 |
| gVisor | システムコールをユーザー空間で横取り | 必要 | 中 | 優秀（正しい構成時） |
| VM／Firecracker | OS 全体、独自カーネル | 不要 | 高 | 優秀（正しい構成時） |
| Claude Code on the web | OS 全体（Anthropic 管理） | 不要 | なし（サブスク要） | Anthropic 管理 VM |

`[S6]` `[S7]`

**押さえておくべき「穴」**
- 組み込み Bash サンドボックスは **MCP サーバーとコマンドフックをカバーしません**。これらはホスト上で無制約に動きます。プロセス全体を包む方式のみがカバーします。`[S6]`
- 分離は**モデルへ何が送られるかを変えません**。プロンプトと Claude が読んだファイルは、サンドボックスの有無に関わらず API に送信されます。`[S6]`
- sandbox-runtime 等のプロキシはクライアント申告のホスト名で許可判定し、**TLS を終端しません**。したがってドメインフロンティングで許可リスト外に到達し得ます。より強い保証が必要なら TLS 終端プロキシを構成してください。`[S7]`
- ホストレベルのサンドボックスはホストカーネルを共有するため、カーネル脆弱性による脱出が理論上あり得ます。`[S7]`
- sandbox runtime は高リスクな書き込みを既定で拒否します（`.git/hooks`、許可しない限り `.git/config`、`.mcp.json`、`.claude/commands`、`.claude/agents`、シェル起動ファイル）。ただし Linux／WSL2 では**セッション中に作成されたパス**へのカバレッジが弱くなります。Claude Code の設定パスに書ける状態のセッションは、**次回起動時にサンドボックス外で動くフック・パーミッションルール・MCP サーバーを永続化できてしまいます**。これらのパスは明示的に deny し、無人実行の後は書き込み可能だったパスをレビューしてください。`[S6]`
- gVisor のコスト：CPU バウンド処理は約 0%、単純なシステムコールは約 2 倍、ファイル I/O 集約型は最大 10〜200 倍。`[S7]`

**コンテナのハードニング** `[S7]`
`--cap-drop ALL`、`--security-opt no-new-privileges`、seccomp プロファイル、`--read-only` ＋ `tmpfs` スクラッチ、`--network none` ＋ Unix ソケットプロキシ、`--memory`／`--pids-limit`、`--user 1000:1000`、コードは `:ro` でマウント。**`~/.ssh`、`~/.aws`、`~/.config` はマウントしないこと。** 読み取り専用マウントでも資格情報は漏れます。`.env`、`~/.git-credentials`、`~/.aws/credentials`、gcloud ADC、`~/.azure/`、`~/.docker/config.json`、`~/.kube/config`、`.npmrc`、`.pypirc`、サービスアカウント JSON、`*.pem`、`*.key` は除外してください。

**出典：** `[S6]` `[S7]`

- **資格情報の分離パターン：** 推奨アーキテクチャは、エージェントの境界の**外側**にプロキシを置き、送信リクエストに資格情報を注入する方式です。エージェントは資格情報を一切見ず、プロキシがエンドポイント許可リストを強制し、全リクエストを集中ログ化します。`[S7]`
- **ゲートウェイ：** Claude Code は自社ホストの LLM ゲートウェイに対応しており、資格情報の集中管理・利用量追跡・コスト統制が可能です。`[S8]`

<a id="t9"></a>
### `T9` — ネットワークとデプロイのセキュリティ

**一言でいうと：** エグレスは、**エージェントが書き換えられない境界**で制御する。

**クラウド実行（Claude Code on the web、Anthropic ホスト）** `[S1]` `[S2]`
- セッションごとに隔離された Anthropic 管理 VM で実行されます。
- ネットワークアクセスは既定で制限され、無効化または特定ドメインのみへの制限も設定可能です。
- GitHub 認証はセキュアプロキシ経由で、サンドボックス内にはスコープ限定の資格情報のみが発行されます。**本物の GitHub トークンはサンドボックスに入りません。**
- git push は現在の作業ブランチに制限されます。
- すべての操作がコンプライアンス・監査目的でログ記録され、送信トラフィックはすべてセキュリティプロキシを通過します。
- セッション VM は一定時間の無活動後に回収されます。セッションは削除可能で、削除するとイベントデータは完全に消去されます。
- **セルフホスト環境**にルーティングされたセッションは自社インフラで動作するため、分離・エグレス・git 資格情報は**自社の責任**になります。`[S1]`

**Remote Control** `[S1]`
- 実行とファイルアクセスはローカルに留まり、通信は Anthropic API 経由の TLS です。接続中はデバイス間同期のためセッショントランスクリプトが Anthropic のサーバーに保存されます。影響範囲を限定するため、それぞれ独立に失効する短命かつ最小スコープの複数資格情報を使用します。

**プロキシ** `[S7]`
- `ANTHROPIC_BASE_URL`：サンプリングリクエストを平文で自社プロキシへ（検査・改変が可能）。
- `HTTP_PROXY`／`HTTPS_PROXY`：全 HTTP トラフィックを経由させますが、HTTPS は不透明な CONNECT トンネルになるため、資格情報注入には TLS 終端プロキシとその CA をエージェントのトラストストアに入れる必要があります。
- すべてのプログラムがプロキシ環境変数を尊重するわけではありません（Node の `fetch()` は Node 24+ で `NODE_USE_ENV_PROXY=1` を設定しない限り無視）。proxychains や iptables による透過プロキシへのリダイレクトも検討してください。
- クラウド構成パターン：インターネットゲートウェイのないプライベートサブネット、自社プロキシ宛て以外のエグレスをファイアウォールで遮断（例：Envoy の `credential_injector`）、エージェントのサービスアカウントは最小 IAM、プロキシで全通信をログ化。

**WebFetch のドメイン安全性チェック** `[S2]`
URL を取得する前に、WebFetch は**ホスト名のみ**（パスやページ内容は送りません）を `api.anthropic.com` に送り、安全性ブロックリストと照合します。通過したホスト名は 5 分キャッシュされます。これは全プロバイダで動作し、`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` では無効化されません。ネットワークで `api.anthropic.com` を遮断している場合、許可リストに追加するか `skipWebFetchPreflight: true` を設定するまで WebFetch は失敗します。後者を選ぶ場合は `WebFetch` のパーミッションルールと併用してください。

**出典：** `[S1]` `[S2]` `[S7]`

- ZDR 組織でも監査ログと Analytics ダッシュボードは利用できますが、コントリビューションメトリクスは利用できません。`[S4]`

<a id="t11"></a>
### `T11` — サプライチェーン・MCP・脆弱性報告

**一言でいうと：** MCP サーバーとコネクタの信頼判断は、Anthropic ではなく**あなたの責任**。

- Claude Code はユーザーによる MCP サーバー設定を許容します。許可リストはソース管理にコミットされる設定内に置かれます。Anthropic のガイダンスは「自作するか、信頼できる提供元のものを使う」ことです。`[S1]`
- Anthropic は Anthropic Directory への掲載前にコネクタを掲載基準に照らしてレビューしますが、**いかなる MCP サーバーもセキュリティ監査・管理はしていません**。`[S1]`
- 組織は managed MCP 設定・許可リスト・拒否リストで MCP サーバーを集中制御できます。`[S8]`
- MCP サーバーとフックは組み込み Bash サンドボックスの**外側**の別プロセスとして動作します（[`T7`](#t7) 参照）。`[S6]`
- サードパーティツール・MCP サーバー・外部連携が処理するデータは **ZDR／HIPAA readiness の対象外**です。各サービスのデータ取り扱いを個別に確認してください。`[S4]` `[S5]`
- **脆弱性報告：** Anthropic は HackerOne でセキュリティプログラムを運用しています。公開開示せず、再現手順を添えて報告し、修正までの時間を確保してください。`[S1]` `[S3]`
- **製品内のセキュアコーディング支援：** security-guidance プラグイン（セッション中に Claude が書いたコードの脆弱性をレビュー・修正）、`/security-review` コマンド（現ブランチの変更に対するオンデマンドのセキュリティパス）、Claude Security プラグイン（コードベースの脆弱性スキャン）、Code Review（PR の脆弱性・リグレッション自動レビュー）。`[S1]` `[S8]`

**出典：** `[S1]` `[S3]` `[S4]` `[S5]` `[S6]` `[S8]`

<a id="faq"></a>
## FAQ

<a id="q1"></a>
### `Q1` 当社のコードやプロンプトはモデルの学習に使われますか？
**商用規約下（Team／Enterprise／API／サードパーティプラットフォーム／Claude Gov）では使われません。** ただし組織が明示的にオプトインした場合（例：Development Partner Program。組織管理者による有効化が必要で、ファーストパーティ API 限定）を除きます。コンシューマプラン（Free／Pro／Max）では、ユーザー自身のプライバシー設定次第です。API 側でも「保持データは許可なく学習に使わない」と明記されています。
→ テーマ [`T2`](#t2) ／ 出典 `[S2]` `[S5]`

<a id="q2"></a>
### `Q2` データはどれくらいの期間保持されますか？
商用の標準は **30 日**です。コンシューマはデータ共有オンで 5 年、オフで 30 日。フィードバック経由のトランスクリプトは 5 年、サーベイで共有したトランスクリプトは最大 6 か月、ローカルの Claude Code トランスクリプトは開発者のディスク上に**平文**で既定 30 日置かれます。組織側のストアは別体系です（Activity Feed 6 年、ローカル／リモートのセッショントランスクリプト既定 6 年）。
→ テーマ [`T2`](#t2) ／ 出典 `[S2]` `[S5]`

<a id="q3"></a>
### `Q3` ZDR とは具体的に何で、すぐ有効化できますか？
ZDR は「API 応答返却後、プロンプトと応答を保存時に保持しない」ことです。**自分では有効化できません。** Anthropic のアカウントチームが適格性を確認したうえで**組織単位**で付与するもので、標準 Enterprise プランには含まれません。重要な点として、**同一アカウント配下の新規組織には継承されません。**
→ テーマ [`T3`](#t3) ／ 出典 `[S4]` `[S5]`

<a id="q4"></a>
### `Q4` ZDR で「カバーされない」のはどこですか（＝後で驚くのはどこですか）？
claude.ai のチャット、Cowork、Claude Console／Playground、Claude Managed Agents、Claude for Excel、コンシューマプラン、ユーザー／シート管理データ、Claude Code の Analytics メタデータ、サードパーティツールや MCP サーバーが処理するデータです。ステートフルな API 機能（Batch、Files、コード実行）はブロックされませんが枠外です。Claude Code の ZDR 下では、Claude Code on the Web、デスクトップのクラウドセッション、Claude Tag、Artifacts、`/feedback`・`/bug`・`/share`、Remote Control が**無効化**されます。
→ テーマ [`T3`](#t3) ／ 出典 `[S4]` `[S5]`

<a id="q5"></a>
### `Q5` Anthropic はどの認証を取得していて、報告書はどう入手しますか？
SOC 2 Type 2 報告書や ISO 27001 証明書を含むコンプライアンス成果物は **[Anthropic Trust Center](https://trust.anthropic.com)** で公開されており、製品ドキュメント自身が入手先としてここを指定しています。制限付き文書も同サイトから請求します。**伝聞の要約を引用せず、Trust Center で最新の一覧と適用範囲を直接確認してください。**
→ テーマ [`T1`](#t1) ／ 出典 `[S1]` `[S3]`

<a id="q6"></a>
### `Q6` PHI を扱う／HIPAA 対象ワークロードを動かせますか？
はい。BAA を締結したうえで Claude API の **HIPAA readiness** を利用します。これは ZDR とは別の枠組みで、PHI にはこちらが正解です（両方は不要）。組織単位で強制され、非適格機能は `400` でブロックされるため、HIPAA 対象外の業務には別組織を使ってください。Claude Code については、当該組織で **ZDR が有効な場合に限り** BAA が Claude Code 経由の API トラフィックに及びます。なお Claude Platform on AWS では HIPAA readiness は利用できません。
→ テーマ [`T3`](#t3) [`T1`](#t1) ／ 出典 `[S3]` `[S5]`

<a id="q7"></a>
### `Q7` Claude Code が破壊的なコマンドを実行しないよう、実際に何が止めているのですか？
Manual モードでは、読み取り専用での開始、コマンド単位の承認、書き込みの作業ディレクトリ境界、未マッチコマンドのフェイルクローズ、許可リスト済みでも再確認を求めるコマンドインジェクション検知、`rm`／`rmdir` の組み込みクリティカルパスチェックと保護パスリスト、そして allow ルールがあっても常に承認が必要な `eval` 系構文です。ただしパーミッション照合は AST ベースの**ゲートであってサンドボックスではなく**、コマンドが特定パスに対して何をするかまでは推論しません。
→ テーマ [`T6`](#t6) [`T5`](#t5) ／ 出典 `[S1]` `[S7]`

<a id="q8"></a>
### `Q8` サンドボックス化すればプロンプトインジェクションは解決しますか？
**いいえ。** サンドボックスは**発生確率ではなく影響**を下げるものです。Anthropic は「ネットワークエグレスを許す方式では、エージェントが読めるデータは依然として漏出し得る」「書き込み可能なプロジェクトマウントは依然として改変され得る」「いかなるシステムも完全免疫ではない」と明言しています。TLS を終端しないプロキシの許可リストはドメインフロンティングで迂回可能です。パーミッション＋分離＋エグレス制御＋監視を**多層で**組んでください。
→ テーマ [`T5`](#t5) [`T7`](#t7) ／ 出典 `[S1]` `[S6]` `[S7]`

<a id="q9"></a>
### `Q9` 無人実行させたいが、暴走させないためには？
`--dangerously-skip-permissions` は**コンテナ・VM・sandbox runtime の外では絶対に使わない**こと。かつ非 root ユーザーで実行してください（Linux／macOS では root だと起動自体が拒否されます）。auto モードの分類器はアクション単位の統制であって境界ではないため、無人実行では分離境界が引き続き多層防御として意味を持ちます。組み込み Bash サンドボックス単体では MCP サーバーとフックが外に残るため、無人実行には不十分です。実行後は書き込み可能だったパスを必ずレビューしてください。
→ テーマ [`T6`](#t6) [`T7`](#t7) ／ 出典 `[S6]`

<a id="q10"></a>
### `Q10` 開発者が個人アカウントを使って組織ポリシーを迂回するのを防ぐには？
`forceLoginMethod` と `forceLoginOrgUUID` のマネージド設定を配布し、claude.ai ログインが自組織に属することを必須化します。これがないと、個人アカウントのセッションは組織の ZDR 契約や設定の対象外になります。
→ テーマ [`T8`](#t8) [`T3`](#t3) ／ 出典 `[S4]` `[S8]`

<a id="q11"></a>
### `Q11` 開発者のマシンから何が出ていき、どう止めますか？
メトリクス（コード・プロンプト・ファイルパスは含まない。`DISABLE_TELEMETRY=1`）、エラーレポート（送出前に秘匿化。`DISABLE_ERROR_REPORTING=1`）、会話履歴を含む `/feedback` 送信（`DISABLE_FEEDBACK_COMMAND=1`）、セッション品質サーベイの評価（`CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1`）です。`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` で一括無効化できます。ただし **2 つは個別対応が必要**：WebFetch のホスト名安全性チェック（`skipWebFetchPreflight`）とマーケットプレイス自動インストール。Bedrock／Google Cloud／Foundry／Claude Platform on AWS では大半が既定でオフです。
→ テーマ [`T2`](#t2) [`T9`](#t9) ／ 出典 `[S2]`

<a id="q12"></a>
### `Q12` MCP サーバーやコネクタは Anthropic が審査していますか？
コネクタは Anthropic Directory への掲載前に掲載基準でレビューされますが、**Anthropic はいかなる MCP サーバーもセキュリティ監査・管理していません**。MCP サーバーは「自社責任のサードパーティコード」として扱ってください。自作するか信頼できる提供元のものを使い、managed MCP の許可／拒否リストで集中制御し、**組み込み Bash サンドボックスの外側で動作し、ZDR／HIPAA の対象外である**ことを忘れないでください。
→ テーマ [`T11`](#t11) ／ 出典 `[S1]` `[S4]` `[S5]` `[S6]` `[S8]`

<a id="q13"></a>
### `Q13` 典型的な攻撃経路である Web コンテンツはどう扱われますか？
Web fetch は**独立したコンテキストウィンドウ**を使い、Web 検索結果は生ではなく**要約**され、`curl`／`wget` は既定で自動承認されず、WebFetch は取得前に `api.anthropic.com` へ**ホスト名のみ**を送って安全性ブロックリストと照合します。自社アプリを作る場合は、取得コンテンツを `tool_result` に入れ、JSON エンコードし、出所を明示し、行動前に分類器でスクリーニングしてください。
→ テーマ [`T5`](#t5) [`T9`](#t9) ／ 出典 `[S1]` `[S2]` `[S7]` `[S12]`

<a id="q14"></a>
### `Q14` Claude Code on the web のセキュリティ特性は？
セッションごとに隔離された Anthropic 管理 VM、既定で制限されたネットワーク（無効化またはドメイン許可リストに設定可能）、セキュアプロキシ経由の GitHub 認証で**本物のトークンはサンドボックスに入らない**、git push は現在のブランチに限定、全操作を監査ログ化、無活動後に VM 回収、セッション削除でイベントデータを完全消去。ただし組織がセルフホスト環境にルーティングしている場合、分離・エグレス・git 資格情報は**自社の責任**になります。
→ テーマ [`T9`](#t9) ／ 出典 `[S1]` `[S2]`

<a id="q15"></a>
### `Q15` Claude の操作ログを SIEM に取り込むには？
イベント単位のレコードには **Compliance API**（`/v1/compliance/*`）を使います（Activity Feed、ディレクトリ、実効設定、チャット／ファイル／プロジェクト、セッショントランスクリプト）。キーは Compliance Access Key（全機能）または Admin API キー（Activity Feed のみ）。リアルタイム送出が必要なら **OpenTelemetry** で自社コレクタへ。claude.ai の監査ログ CSV エクスポートは遡及期間に上限がありコンテンツも含まないため、継続的な連携の基盤には適しません。
→ テーマ [`T10`](#t10) ／ 出典 `[S13]` `[S1]`

<a id="q16"></a>
### `Q16` ZDR 下でも Anthropic がデータを保持することはありますか？
**あります。** 法令上必要な場合、および自動化された Trust & Safety システムが内容をフラグした場合で、後者では入力と出力が**最大 2 年間**保持され得ます。これは例外的なエッジケースではなく文書化された意図的な例外なので、リスク登録簿に記載してください。
→ テーマ [`T3`](#t3) [`T2`](#t2) ／ 出典 `[S4]` `[S5]`

<a id="q17"></a>
### `Q17` Claude API を直接使うか、Bedrock／Google Cloud／Foundry 経由かで違いはありますか？
**実質的に大きく違います。** **Claude API・Claude Platform on AWS・Claude in Microsoft Foundry では Anthropic がデータ処理者**であり、本ページの ZDR／HIPAA の枠組みが適用されます。一方、**Amazon Bedrock と Google Cloud's Agent Platform ではクラウドプロバイダがデータ処理者**であり、適用されるのは各社の保持・コンプライアンスポリシーです。保存時暗号化やテレメトリの既定値もプロバイダごとに異なります。
→ テーマ [`T2`](#t2) [`T3`](#t3) ／ 出典 `[S2]` `[S5]`

<a id="q18"></a>
### `Q18` Claude Code に脆弱性を見つけました。どうすればよいですか？
**公開開示しないでください。** Anthropic の HackerOne プログラムに、詳細な再現手順を添えて報告し、公開前に修正の時間を確保してください。
→ テーマ [`T11`](#t11) ／ 出典 `[S1]` `[S3]`

<a id="q19"></a>
### `Q19` パーミッションモードとサンドボックスは何が違いますか？
パーミッションモードは「**そのツール呼び出しが実行されるか、事前に確認されるか**」を決めます。分離は「**実行された後、そこから何に到達できるか**」を決めます。両者は補完関係にあり、モードが確認を止めた時点で、システムを守るのは分離境界だけになります。auto モードの分類器はアクション単位の統制であって境界ではありません。
→ テーマ [`T6`](#t6) [`T7`](#t7) ／ 出典 `[S6]`

<a id="q20"></a>
### `Q20` ZDR 下で使えないモデルがあるのはなぜですか？
Claude Fable 5.1、Mythos 5.1、Fable 5、Mythos 5 は **Covered Models** に指定され 30 日のデータ保持が必須のため、Anthropic が明示的に許可しない限り ZDR では利用できません。API では要件を満たさないリクエストが `400 invalid_request_error` を返します。ZDR 組織は**特定ワークスペースのみ** 30 日保持を有効化して利用し、他はゼロ保持を維持できます。
→ テーマ [`T3`](#t3) ／ 出典 `[S4]` `[S5]`

<a id="q21"></a>
### `Q21` プロンプトがモデルに届く「前」に遮断できますか？
はい。**Inference hooks**（ベータ）により、自組織の AI セキュリティサーバーが推論前に対象プロンプトを受け取り、リアルタイムで拒否できます。これがインラインの統制であり、Compliance API と OpenTelemetry は事後・観測用です。
→ テーマ [`T10`](#t10) [`T5`](#t5) ／ 出典 `[S13]`

<a id="q22"></a>
### `Q22` Claude 自身に自分の出力の脆弱性を確認させられますか？
できます。**security-guidance プラグイン**はセッション中に Claude が書いたコードの脆弱性をレビュー・修正し、**`/security-review`** は現ブランチの変更にオンデマンドでセキュリティパスをかけ、**Claude Security プラグイン**はコードベースをスキャンし、**Code Review** は PR の脆弱性とリグレッションを自動レビューします。ただしこれらは**レビューの厚みを増すもの**であり、人手のレビューや既存の SAST／DAST を置き換えるものではありません。
→ テーマ [`T11`](#t11) [`T5`](#t5) ／ 出典 `[S1]` `[S8]`
