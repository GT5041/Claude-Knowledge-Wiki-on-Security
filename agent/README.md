# Claude Code 実装方針アドバイザー

質問者が「Claude Code で実装したいこと」を自然文で入力すると、**実装案**と**セキュリティ上の考慮事項**を Markdown レポートとして出力する対話型 CLI エージェントです。

方針決定に必要な情報が足りない場合は、**決まった質問フォーマットでエージェントから質問**し、回答を得てからレポートを作成します。

---

## 動作の流れ

```
 質問者が要求を入力
        │
        ▼
 ①要件の充足判定 ──── ready ────┐
        │                        │
    need_info                    │
        │                        │
        ▼                        │
 ②質問フォーマットで質問         │
   （選択肢つき・最大4件）        │
        │                        │
        ▼                        │
 ③質問者が回答 ──► ①へ戻る       │
   （最大 3 ラウンド）            │
                                 ▼
                       ④レポート生成（Markdown ファイル）
```

- 情報が十分なら質問せずにレポートへ進みます。**「あれば嬉しい」程度の情報のためには質問しません。**
- 未回答の質問には**安全側の仮定**を自動で置き、レポートの「置いた仮定」に明記します。
- 質問ラウンドの上限に達した場合も、その時点の情報でレポートを作成します。

## セットアップ

```bash
pip install -r agent/requirements.txt

# 認証（いずれか）
export ANTHROPIC_API_KEY=sk-ant-...
#  または `ant auth login` 済みのプロファイル（環境変数なしで動作します）
```

## 使い方

```bash
# 対話モード（要求も対話的に入力）
python3 agent/implementation_advisor.py

# 要求をコマンドラインで渡す
python3 agent/implementation_advisor.py -r "社内APIの統合テストをCIで自動生成したい"

# 質問なしで即レポート（要求が十分固まっている場合）
python3 agent/implementation_advisor.py -r "..." --max-rounds 0

# 出力先を変える / 生 JSON も保存する
python3 agent/implementation_advisor.py -r "..." --out ./out --json
```

レポートは `agent/reports/YYYYMMDD-HHMMSS-<タイトル>.md` に出力されます。

## 質問フォーマット

```
■ Q1 [対象データ] 対象リポジトリに顧客データや個人情報は含まれますか？
  └ なぜ聞くか: 含まれる場合、ZDR やデータ保持の要件が加わり実装案が変わります。
     1. 含まれない — テスト用のダミーのみ。
     2. 含まれる — 本番相当データがある。
     0. わからない／未定 → 仮定「機微データを含むものとして扱う」を置いて進めます

Q1 への回答 > 1
```

| 要素 | 意図 |
|---|---|
| `[カテゴリ]` | 目的・スコープ／対象データ／実行環境／権限・自動化／既存資産・制約／コンプライアンス／運用・体制 の 7 分類 |
| `なぜ聞くか` | **回答によって実装案やセキュリティ要件がどう変わるか**。質問の言い換えは禁止している |
| `1. 2. 3.` | 番号で即答できる選択肢（2〜4 個）。`★推奨` 付きのものがあれば現時点の推奨 |
| `0.` | 不明・未定。安全側の仮定を置いて進む |

番号のほか**自由記述でも回答できます**。空欄（Enter のみ）は「未回答」として仮定が適用されます。

## レポートの構成

| 節 | 内容 |
|---|---|
| 1. 元の要求 | 入力をそのまま記録 |
| 2. 要求の理解 ＋ 置いた仮定 | 認識齟齬を先に潰すための節。**仮定が違えば結論が変わる**ことを明示 |
| 3. 実装案 | **トレードオフの異なる 2〜3 案**。手順・使用機能・利点・欠点・工数・適する条件。推奨案を 1 つ明示 |
| 4. セキュリティ考慮事項 | 重大度順。各項目に観点 ID（`SEC-xx`）と Wiki の ID（`T#`/`Q#`）を紐づけ |
| 5. 残論点 | エージェントでは判断できず質問者側の確認が要る事項 |
| 6. 次のアクション | 具体的な次の一手 3〜5 項目 |
| 付録 | 確認のやり取りの記録 |

出力フォーマットの見本: [`samples/sample_report.md`](samples/sample_report.md)

## セキュリティ考慮事項の出どころ

[`knowledge/security_checklist.md`](knowledge/security_checklist.md) が知識源です。14 の観点（`SEC-01`〜`SEC-14`）を持ち、それぞれが本リポジトリの [Claude セキュリティ Wiki](../wiki/Claude-Security.ja.md) のテーマ ID（`T#`）・FAQ ID（`Q#`）に紐づいています。

レポートの各項目は `SEC-xx` と `T#`/`Q#` を併記するため、**読者はレポートから Wiki の該当節へ遡れます**。

エージェントには次を守らせています。

- **該当しない観点は書かない。** 網羅より関連性を優先する（一般論のチェックリストの貼り付けを防ぐ）。
- **重大度は「権限 × 到達範囲 × 非信頼入力の有無」で判断する。**
- **緩和策は設定名・コマンド・構成レベルで書く。**「注意する」は緩和策として認めない。
- 外部由来のコンテンツに触れる実装なら**間接プロンプトインジェクション（SEC-04）を必ず含める**。
- 無人実行・自動実行を含むなら**権限モデル（SEC-05）と分離（SEC-06）を必ず含める**。

Wiki ファイルが存在する場合は ID 対応付けの参照用として自動で読み込みます（無くても動作します）。

## 実装メモ

| 項目 | 選択 | 理由 |
|---|---|---|
| モデル | `claude-opus-5` | 設計判断とセキュリティ分析を伴うため |
| 思考 | `thinking: {"type": "adaptive"}` ＋ `effort: high` | トレードオフの比較を要するタスク |
| 出力 | structured outputs（Pydantic ＋ `messages.parse`） | 質問とレポートの構造を型で固定し、CLI 側の描画を安定させるため |
| キャッシュ | システムプロンプト末尾に `cache_control` | 知識源（約 36,000 文字）は全ターン同一なのでキャッシュが効く |
| 拒否対応 | サーバーサイドフォールバック → 非対応環境では通常パスへ縮退 | `stop_reason: "refusal"` を握り潰さず明示的に扱う |

対話の各ターンで `messages` に構造化出力をそのまま積んでいるため、2 ラウンド目以降の質問は**前回の回答を踏まえたもの**になります。

## 検証状況

| 対象 | 状況 |
|---|---|
| 知識源の読み込み、システムプロンプト構築、キャッシュ指定 | ✅ 確認済 |
| 質問フォーマットの描画 | ✅ 確認済 |
| 回答収集の全経路（番号選択／`0` で仮定／自由記述／範囲外→再入力／空欄） | ✅ 確認済 |
| レポートの Markdown 整形 | ✅ 確認済（ダミーデータ） |
| CLI 引数、構文 | ✅ 確認済 |
| **実 API を用いたエンドツーエンド実行** | ⚠️ **未実施** — 開発環境に API 資格情報が無いため |

**API 呼び出し部分（`call_model`）は実行検証していません。** 初回実行時は `--max-rounds 0` などで短く試し、エラーが出た場合はメッセージを共有してください。特に `client.beta.messages.parse` に `fallbacks` を渡す経路は環境によって非対応の可能性があり、その場合は自動で通常パスへ縮退する実装にしています。

## 制約

- 生成されるのは**たたき台**です。セキュリティ考慮事項の網羅性は保証されません。本番適用前に自社のセキュリティ／コンプライアンス担当のレビューを受けてください。
- リポジトリの実コードは読みません。入力された自然文のみから判断します。コードベースに即した助言が必要な場合は、Claude Code 上で直接相談してください。
- 知識源は本リポジトリの Wiki に準拠します。Wiki 側の記述が古くなればレポートの前提も古くなります（Wiki の[メンテナンス](../wiki/Claude-Security.ja.md#maintain)参照）。
